Build a horde-survival game on a clean, data-driven skeleton.

VSS Framework is a reusable architecture for bullet-heaven games: a data-driven character with auto-firing weapons and passive accessories, hordes of enemies, XP gems, level-up choices, and a timed stage. This guide explains what connects to what and shows exactly how to add your own content.

§Overview

VSS Framework provides the genre's core loop out of the box: a data-driven player character with auto-firing weapons and passive accessories, hordes of enemies that chase and damage you, experience gems dropped on death, a level-up screen that pauses the game and offers three random upgrades, and a timed stage with a spawn director that ramps difficulty.

Everything that varies between characters, weapons, accessories, enemies and stages is data, not code. You extend the framework by registering definitions and, when you need custom behaviour, by subclassing one small hook.

Requirements

Godot 4.3 or newer. This guide is the deep companion to the project's README.md, which is the quick overview.

§Before & after

Same feature, with and without the framework

The framework's whole point is to replace boilerplate with data. Here is the same feature written without the framework, then with it.

An auto-firing weapon

Before — two scripts and ~30 lines of boilerplate just to fire one projectile at the nearest enemy, with no stat scaling, piercing, or level-up support:

# player.gd — raw Godot
extends CharacterBody2D

var cooldown := 1.2
var damage := 8.0
var timer := 0.0
var projectile_scene := preload("res://projectile.tscn")

func _physics_process(delta: float) -> void:
    timer -= delta
    if timer <= 0.0:
        timer = cooldown
        fire()

func fire() -> void:
    var enemies := get_tree().get_nodes_in_group("enemies")
    if enemies.is_empty():
        return
    var origin := global_position
    enemies.sort_custom(func(a, b):
        return origin.distance_squared_to(a.global_position) < origin.distance_squared_to(b.global_position))
    var proj := projectile_scene.instantiate()
    proj.damage = damage
    proj.direction = (enemies[0].global_position - origin).normalized()
    proj.global_position = origin
    get_tree().current_scene.add_child(proj)
# projectile.gd — raw Godot
extends Area2D

var damage: float
var direction: Vector2
var speed := 400.0
var lifetime := 2.0

func _physics_process(delta: float) -> void:
    global_position += direction * speed * delta
    lifetime -= delta
    if lifetime <= 0.0:
        queue_free()

After — a four-line subclass plus a data registration. Targeting, cooldown, spawning, pierce, stat scaling and level-up integration are all handled for you:

# content/weapons/wand.gd — with the framework
class_name Wand
extends Weapon
## The base Weapon handles cooldown, targeting, spawning and scaling.
var wand := WeaponData.new()
wand.id = "wand"
wand.base_stats = _stats({"power": 8.0, "cooldown": 1.2, "speed": 400.0, "duration": 2.0})
wand.weapon_script = preload("res://content/weapons/wand.gd")
DataManager.register_weapon(wand)

A chasing enemy

Before — chasing, contact damage, and the XP drop are all hand-rolled:

# enemy.gd — raw Godot
extends CharacterBody2D

var hp := 10.0
var move_speed := 90.0
var contact_damage := 5.0
var xp_value := 1.0
var attack_timer := 0.0

func _physics_process(delta: float) -> void:
    var player := get_tree().get_first_node_in_group("player")
    if player == null:
        return
    velocity = (player.global_position - global_position).normalized() * move_speed
    move_and_slide()
    attack_timer -= delta
    if attack_timer <= 0.0 and global_position.distance_to(player.global_position) < 20.0:
        attack_timer = 0.5
        player.take_damage(contact_damage)

func take_damage(amount: float) -> void:
    hp -= amount
    if hp <= 0.0:
        var gem := preload("res://gem.tscn").instantiate()
        gem.value = xp_value
        gem.global_position = global_position
        get_tree().current_scene.add_child(gem)
        queue_free()

After — override only the visuals; movement, contact damage, and the XP drop come from Enemy:

# content/enemies/chaser.gd — with the framework
class_name Chaser
extends Enemy

func _draw() -> void:
    draw_circle(Vector2.ZERO, 12.0, Color(0.9, 0.4, 0.2))
var chaser := EnemyData.new()
chaser.id = "chaser"
chaser.max_hp = 10.0
chaser.move_speed = 90.0
chaser.contact_damage = 5.0
chaser.xp_value = 1.0
chaser.enemy_script = preload("res://content/enemies/chaser.gd")
DataManager.register_enemy(chaser)

Same story for accessories, characters and stages — a data definition plus, at most, one small override.

§The big picture

Six layers, one-way data flow

The framework is an addon: its code lives under addons/vss_framework/, split into six layers. Your own game content lives outside the addon, in your project's own folders.

Layer (under addons/vss_framework/)What lives there
demo/Entry scene — registers content, builds the world, starts a run.
autoload/Singletons — SignalBus, DataManager, GameManager.
data/Resource classes that describe a thing (weapon, enemy, …).
objects/Runtime gameplay nodes/objects (player, enemy, projectile, …).
systems/Recurring logic — spawn pacing and level-up choice generation.
ui/HUD and the level-up screen (both built in code).
content/The example content you replace with your own game's content.

Data flows one way. Content is registered into DataManager as Resource instances. Runtime objects look data up by string id and are constructed from the script a data entry points at. Systems never reach into each other; they talk through SignalBus signals. GameManager owns the high-level run state.

A single frame

# per frame
GameManager._process         → advance timer, check win
CharacterController._physics → input, move, regen, drive weapons/accessories
SpawnDirector._process       → spawn an enemy when the timer expires
Enemy._physics_process       → chase player, deal contact damage
Projectile._physics_process  → move, hit enemies
Pickup._physics_process      → magnet toward player, grant XP on contact

§Boot sequence

When you press F5, Godot loads addons/vss_framework/demo/main.tscn — a bare Node2D with addons/vss_framework/demo/main.gd attached. Its _ready() runs three steps in order:

  1. Register content — ExampleContent.register_all() registers the demo character, weapons, accessory, enemies and stage into DataManager.
  2. Build the world — _setup_world() adds a SpawnDirector, a LevelUpSystem, a HUD, and a LevelUpScreen as children of the main node.
  3. Start the run — _start_run() creates a CharacterController, assigns it the "demo" data, adds it to the tree, attaches a Camera2D, then calls GameManager.start_run(character, stage).
Your entry point

To ship your own game, write your own content registration (a copy of ExampleContent, or .tres resources), register your own character and stage, and build your own main scene. The demo in addons/vss_framework/demo/ is the reference.

§The three autoloads

Singletons registered by the plugin

Autoloads are created in declaration order before the main scene loads, so any script can refer to them by name: SignalBus, DataManager, GameManager.

SignalBus

The event bus. Systems subscribe to signals here instead of holding references to each other. See the signals reference for who emits and listens to each one.

DataManager

The central registry. It holds five dictionaries keyed by string id:

DictionaryRegisterLook up
charactersregister_character(data)get_character(id)
weaponsregister_weapon(data)get_weapon(id)
accessoriesregister_accessory(data)get_accessory(id)
enemiesregister_enemy(data)get_enemy(id)
stagesregister_stage(data)get_stage(id)

weapon_ids() and accessory_ids() return every registered id and are used by the level-up system to offer "new item" choices.

GameManager

Owns a run's high-level state and the win/lose transitions:

MemberMeaning
playerThe active CharacterController, or null.
stage_dataThe current StageData.
elapsedSeconds since start_run.
is_runningtrue while a run is being played.
world_rectWorld bounds; clamps the player and constrains spawns.

Key methods: start_run(player, stage), pause() / unpause() (toggle get_tree().paused), spawn(node) (adds a node to the current scene), and _win() / _lose() (emit the corresponding signal and stop the clock).

§The data layer

Resource classes that describe a thing

Every "thing" is a Resource subclass in addons/vss_framework/data/. You register an instance by id; gameplay code reads it back and constructs the matching runtime object.

ModifierStats

The shared stat bag — every field is an exported float (or int) so values are visible in the inspector. Helpers: reset(), add(other), and scaled(factor). The fields the base gameplay uses today:

StatMeaningUsed by
power+% weapon damageweapons scale damage
area+% weapon areaweapons scale hit radius
speed+% projectile speedweapons scale speed
duration+% projectile lifetimeweapons scale duration
cooldown−% weapon cooldownweapons scale cooldown
amount+ projectiles per shotweapons add to amount
move_speedpx/s movementcharacter movement
max_hpmaximum healthcharacter health
magnet+ pickup radius (px)pickup magnet
growth+% XP gainedXP gain
armorflat damage reduction per hitdamage taken
regenhealth per secondcharacter regen

The remaining fields (luck, greed, shields, revivals, rerolls, skips, curse, banish, shroud, charm, defang, thorns, invul_time_bonus, fever, recycle) are reserved placeholders for you to wire up — see Extension points.

The other data classes

ClassDescribes

WeaponDataid, name, max_level, base_stats, level_bonus, pierce, weapon_script, projectile_scene, is_area_weapon.

§The object layer

Runtime gameplay objects

Equipment hierarchy

Equipment (RefCounted)   — not a Node; owned and driven by the character
├── Weapon               — auto-fires on a cooldown
└── Accessory            — passive; grants stats to its owner

Equipment holds owner and level, and defines is_max_level(), level_up(), update(delta), and display_name(). Because it is a RefCounted (not a Node), its lifetime is owned by the CharacterController that holds it in a list and calls update() every frame.

CharacterController

The player. Owns weapons and accessories arrays plus three stat layers — base_stats, level_bonus, and the cached effective stats. recalculate_stats() recomputes:

stats = base_stats + level_bonus + Σ accessory.get_current_stats()

then reads max_hp, move_speed and magnet_radius off the result. Each frame _physics_process moves the player, applies regen, and calls update(delta) on every weapon and accessory. Methods you'll call from content or systems: add_weapon(data), add_accessory(data), find_weapon(id), find_accessory(id), take_damage(amount), gain_xp(amount).

Weapon

Auto-fires on a cooldown. update() counts down the cooldown and calls fire(), which delegates to _fire() — the hook subclasses override. The default _fire() launches projectiles at the nearest enemies. Stat accessors scale the weapon's per-level numbers by the owner's effective stats:

AccessorFormula
get_damage()power × (1 + owner.power)
get_cooldown()max(0.05, cooldown × (1 − owner.cooldown))
get_area()area × (1 + owner.area)
get_speed()speed × (1 + owner.speed)
get_duration()duration × (1 + owner.duration)
get_amount()max(1, amount + owner.amount)
get_pierce()weapon_data.pierce

The weapon's own per-level numbers come from _level_stats(): base_stats + level_bonus × (level − 1).

Accessory

Passive. get_current_stats() returns stats + level_bonus × (level − 1), which the owner folds into recalculate_stats().

Enemy, Projectile, Pickup

  • Enemy (CharacterBody2D) — chases the player, deals contact damage on a 0.5s cooldown via a child Area2D, and drops a Pickup gem on death. take_damage() is guarded so a single enemy dies (and drops) exactly once even if multiple projectiles hit it in one frame.
  • Projectile (Area2D) — moves in a straight line, damages the first enemies it touches, and expires after pierce hits or lifetime seconds.
  • Pickup (Area2D) — sits still until the player is within 60 + player.stats.magnet px, then flies toward them and grants XP on contact.

Collision layers

LayerUsed by
1CharacterController (player)
2Enemy (detected by projectiles)
4Projectile
8Pickup

Masks: the player body masks nothing (movement is manual); enemies use a child Area2D masked to layer 1 to sense the player; projectiles mask layer 2; pickups mask layer 1.

§Systems

SpawnDirector

Spawns enemies over time. Each frame it counts down _spawn_timer; on expiry it resets the timer to _current_interval() and, if the live enemy count is under stage_data.max_enemies, calls _spawn_enemy(). The interval starts at spawn_interval and shrinks by spawn_ramp each minute (down to a 0.1s floor).

LevelUpSystem

When player_leveled_up fires it builds up to three random UpgradeChoices — upgrades for owned weapons/accessories that aren't max level, new weapons/accessories the player doesn't own (capped at 6 of each), and flat stat boosts from STAT_BOOSTS. It pauses the game, emits level_up_choices_ready, and later apply_choice() applies the pick, unpauses, and re-checks for a follow-up level.

§UI

Both UI layers are built entirely in code (no scene files) and driven by SignalBus:

  • HUD (CanvasLayer, layer 5) — timer, HP, level and XP bar. Listens to player_hp_changed, xp_changed, player_leveled_up, game_over, game_won.
  • LevelUpScreen (CanvasLayer, layer 10) — shows one button per choice. Its process_mode is PROCESS_MODE_ALWAYS so buttons stay clickable while the tree is paused.

§Content registration

addons/vss_framework/content/example_content.gd is a RefCounted with a static register_all() that builds every demo definition in code and pushes it into DataManager. Its _stats({...}) helper constructs a ModifierStats from a dictionary of property/value pairs:

static func _register_weapons() -> void:
    var wand := WeaponData.new()
    wand.id = "wand"
    wand.display_name = "Wand"
    wand.max_level = 8
    wand.base_stats = _stats({"power": 8.0, "cooldown": 1.2, "speed": 400.0, "duration": 2.0, "amount": 1.0})
    wand.level_bonus = _stats({"power": 2.0, "cooldown": -0.08})
    wand.pierce = 0
    wand.weapon_script = preload("res://addons/vss_framework/content/weapons/wand.gd")
    wand.is_area_weapon = false
    DataManager.register_weapon(wand)

You can keep registering in code, or build the same objects as .tres resources and edit them in the inspector — either way, gameplay code only ever calls DataManager.get_*.

§How to add…

Recipe book

Each recipe assumes you add files to your own project — the examples use a top-level content/ folder, but any path works as long as your preload points at it. Register each definition from your own content class (a copy of ExampleContent) or a .tres resource, then reference it by id.

A projectile weapon

Create a Weapon subclass — for a plain projectile weapon you usually need no code at all, since the base _fire() already launches projectiles:

# content/weapons/laser.gd
class_name Laser
extends Weapon
## Fires a fast bolt at the nearest enemy. Default _fire() behaviour.
var laser := WeaponData.new()
laser.id = "laser"
laser.display_name = "Laser"
laser.description = "Fires a piercing bolt."
laser.max_level = 8
laser.base_stats = _stats({"power": 12.0, "cooldown": 0.9, "area": 8.0, "speed": 600.0, "duration": 1.5, "amount": 1.0})
laser.level_bonus = _stats({"power": 3.0, "cooldown": -0.06})
laser.pierce = 1
laser.weapon_script = preload("res://content/weapons/laser.gd")
laser.is_area_weapon = false
DataManager.register_weapon(laser)

To make it a starting weapon, add "laser" to the character's starting_weapons. To make it appear in level-ups, do nothing — the level-up system offers every registered weapon automatically.

An area weapon

Override _fire() to damage enemies within get_area() instead of firing projectiles:

# content/weapons/nova.gd
class_name Nova
extends Weapon

func _fire() -> void:
    var radius := get_area()
    var damage := get_damage()
    for enemy in owner.get_tree().get_nodes_in_group("enemies"):
        if owner.global_position.distance_to(enemy.global_position) <= radius:
            enemy.take_damage(damage)

Then register its WeaponData with is_area_weapon = true (and no projectile_scene).

A stat-boost option

Append a dictionary to the STAT_BOOSTS constant in level_up_system.gd:

{"stat": "luck", "value": 0.10, "label": "Fortune", "desc": "+10% luck"},

The stat key must match a ModifierStats property, value is the flat increment, and label/desc are the card text. (luck is a placeholder unless you wire it up.)

§Extension points

The seams designed for you to override or subscribe to

  • Weapon targeting — override Weapon._enemies_by_distance() to change how targets are chosen (nearest, random, strongest, …).
  • Spawn waves — override SpawnDirector._current_interval() or _spawn_enemy() for scripted waves or boss events.
  • Level-up pool — edit LevelUpSystem.STAT_BOOSTS and the choice generator.
  • Meta-progression / unlocks — add a new autoload (register it in project.godot) that tracks persistent unlocks across runs and subscribes to enemy_died, pickup_collected, run_started, …
  • Placeholder stats — luck, greed, shields, curse, thorns, and the rest are unused until you wire them: read them in CharacterController (e.g. apply thorns in take_damage, use luck in a crit roll).
  • Visuals — every entity draws a placeholder circle in _draw(). Replace with Sprite2D / AnimatedSprite2D and real assets.

§Conventions & gotchas

  • Equipment is a RefCounted, not a Node. Don't add it to the tree; the owning CharacterController holds it in an array and drives update().
  • _process vs _physics_process. Movement, combat and equipment updates use _physics_process (fixed timestep); timers, spawn pacing and the HUD clock use _process.
  • Pause semantics. GameManager.pause() sets get_tree().paused. Only nodes with PROCESS_MODE_ALWAYS keep processing — that's how the game freezes behind the choice screen.
  • Spawning. Use GameManager.spawn(node) for anything created at runtime (projectiles, pickups, enemies) so it lands in the current scene without a world reference.
  • Set enemy_data before adding to the tree. Enemy._ready() reads it, so assign it before GameManager.spawn(enemy) (the spawn director already does this).
  • Collision layers are the table in the object layer. Keep player=1, enemy=2, projectile=4, pickup=8, or update the masks to match.
  • Three bugs found during review are fixed: the missing player_died signal (game over is now reachable), the enemy double-death guard (one gem per kill), and the level-up unpause ordering (a second level-up re-pauses correctly).
